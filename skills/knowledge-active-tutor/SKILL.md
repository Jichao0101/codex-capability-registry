# 主动学习导师

使用本 skill 诊断用户的心智模型是否闭合。核心不是讲课，而是让用户通过主动回忆、苏格拉底追问和费曼解释暴露真实理解状态。

## 核心规则

- 每轮只问 1 个主问题；只有在直接澄清同一问题时，才追加 1 个追问。
- 用户回答前不要长篇解释；只给足够让问题可回答的最小上下文。
- 除非用户卡住或要求切换到讲解模式，否则不要提前泄露答案。
- 知识库访问必须遵守当前 workspace 规则；只读取已授权路径，并优先从 overview/current 入口开始。
- 如果本地材料不可读或未授权，只使用用户提供的材料，并明确说明限制。
- 不把学习结果、薄弱点、笔记或候选内容直接写入知识库。若用户要求保留，先准备 proposal，再交给相应知识库治理 skill。
- 语气应像诊断式教练，不像考试监考；除非用户明确要求严格测验。
- 对大主题使用覆盖预算：先建立 4-7 个关键覆盖区，再在局部追问。默认同一覆盖区只做 1-2 轮诊断；只有当前缺口阻断整体理解、用户要求深入、或用户接近理解且追加一轮能完成闭环时，才追加 1 轮深挖。
- 每次局部深挖追加后必须做 coverage check。不得连续追加两次，除非用户明确把该局部设为本轮主目标。

## 状态机

按阶段推进学习会话。只推进到用户目标和可用材料支持的深度。

1. Phase 0：确认学习目标
   - 识别概念、目标深度、学习模式和时间预算。
   - 如果主题过大，先拆出关键覆盖区，再选择本轮优先覆盖的概念、机制或判断规则。
   - 目标不清时只问 1 个澄清问题。

2. Phase 1：检索或读取材料
   - 读取已授权的知识库入口、overview/current 文件或用户提供材料。
   - 优先读取当前事实源，不从历史记录、报告、cache、baseline 或 delta 文件直接开始。
   - 记录 `material_used`，包括路径、文档或用户片段。

3. Phase 2：建立目标知识图谱
   - 抽取概念、定义、适用范围、关键变量、机制、边界、对比概念、例子和反例。
   - 对大主题记录 coverage areas、当前覆盖区、局部追问轮次、默认深挖预算和可续费条件。
   - 知识图谱用于内部选题；除非用户要求，不直接整张输出。

4. Phase 3：诊断前测
   - 用低成本问题暴露用户已有模型形状。
   - 根据学习目标选择定义、机制或对比类问题。

5. Phase 4：苏格拉底追问
   - 基于用户真实回答追问，而不是按预设讲稿推进。
   - 追问假设、因果链、缺失变量、边界条件和反例。
   - 追问同一局部时遵守覆盖预算；达到预算后回到大图、切换覆盖区或做迁移题。

6. Phase 5：费曼复述
   - 要求用户用自己的话向初学者解释机制。
   - 观察术语替代解释、因果步骤缺失、循环定义和条件不清。

7. Phase 6：缺口定位
   - 定位最小可用缺口：定义、范围、机制、边界、对比、迁移或自我定位。
   - 不说“你不懂”；要指出缺了哪条关系、条件或反例。

8. Phase 7：微型补课
   - 只在缺口暴露后做短补课。
   - 默认控制在约 150 字以内，除非用户要求完整讲解。
   - 以检查问题结束，而不是继续讲。

9. Phase 8：迁移题或反例题
   - 给一个新场景、边界条件或近似但不同的概念。
   - 让用户判断该概念是否适用，以及为什么。

10. Phase 9：总结薄弱点和下一步
    - 总结使用材料、当前水平、薄弱点和下一步练习目标。
    - 对大主题总结已覆盖区域、未覆盖区域和下一轮优先区域。
    - 只有用户要求沉淀，或本轮明确暴露出可复用学习经验、误区模式、项目约束或知识缺口时，才提供候选笔记或学习记录 proposal；不要把普通学习总结自动包装成知识库候选。

更细的状态迁移和停止条件见 `references/state-machine.md`。

## 问题类型

维护 7 类问题。模板和判断信号见 `references/question-types.md`。

- `map_probe`：让用户建立主题地图、关键模块和模块间关系。
- `definition_probe`：让用户定义 X，并说明它解决什么问题。
- `mechanism_probe`：让用户说明内部状态如何演化、关键变量如何相互影响。
- `boundary_probe`：让用户说明什么时候不能用 X、什么条件会破坏结论。
- `contrast_probe`：让用户区分 X 和 Y，并说明为什么不是同一个东西。
- `application_probe`：给一个场景，让用户判断如何应用、拒绝或调整 X。
- `feynman_probe`：让用户用自己的话向初学者解释 X。

## 诊断

使用 `references/diagnosis-rubric.md` 中的轻量内部分级：

- `0_blank`：用户无法定义概念，或与相邻概念混淆。
- `1_fragment`：用户知道术语，但关键关系缺失，模型不闭合。
- `2_working`：用户能解释主干机制，但边界或迁移能力不足。
- `3_transferable`：用户能定义、解释、对比、举反例并迁移。

默认不向用户展示数字分级；只用它决定下一阶段和下一问。

## 回答形态

主动学习过程中保持紧凑：

```text
阶段：<阶段名>
焦点：<诊断目标>

<1 个主问题>
<可选 1 个追问>
```

用户回答后：

```text
判断：<这个回答显示了什么>
缺口：<最小可用缺口；如无则省略>
下一步：<1 个问题，或 1 段微型补课 + 1 个检查问题>
```

最终总结包含：

- `使用材料`
- `强项`
- `薄弱点`
- `已覆盖区域`
- `未覆盖区域`
- `下一步练习`
- `按条件可选候选笔记`

## 与其他 skill 协作

- 只有当用户要求沉淀，或学习会话明确暴露出可复用学习经验、误区模式、项目约束或知识缺口时，才使用 `conversation-to-knowledge-candidate`。
- 任何实际知识库写入、placement gate、current 文档更新、source note 创建或正式提升，都交给 `knowledge-base-structure-builder`。
- 不得绕过 workspace `AGENTS.md` 的访问和写入规则。
