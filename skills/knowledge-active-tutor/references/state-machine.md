# 状态机

当学习会话超过单个问题时使用本参考。可以向用户简短标出当前阶段，但不要把状态机本身讲成课程内容。

## Phase 0：确认学习目标

输入：
- 用户提出的主题。
- 用户声明的模式，例如测验、费曼法、复习、面试或考试。

动作：
- 识别主题、目标深度、上下文、时间预算，以及用户想要严格测试还是教练式引导。
- 如果主题过大，收敛到一个概念、机制或判断规则。

进入下一阶段的条件：
- 概念和目标深度足够清楚，可以选择材料。

可问：
- “这轮学习你希望达到什么程度：能定义、能应用、能解释机制，还是能处理边界反例？”

## Phase 1：检索或读取材料

输入：
- 已授权的知识库路径。
- 用户提供文本。
- workspace 访问规则。

动作：
- 如果存在 overview/current 入口，先读入口。
- 读取最小的直接相关事实源。
- 记录 `material_used`。

阻塞条件：
- 没有授权材料，且用户未提供足够上下文。

进入下一阶段的条件：
- 材料足够建立目标知识图谱。

## Phase 2：建立目标知识图谱

用以下结构表示目标概念：

```yaml
concept:
definition:
problem_solved:
scope:
key_variables:
mechanism:
boundaries:
contrasts:
examples:
counterexamples:
transfer_tasks:
```

该图谱默认只供内部使用。只有用户要求“给我知识地图”时才输出。

## Phase 3：诊断前测

从成本最低、最能暴露结构的问题开始：

- 不熟悉概念：`definition_probe`
- 知道术语但过程不清：`mechanism_probe`
- 容易和邻近概念混淆：`contrast_probe`
- 用户自称有把握：`boundary_probe` 或 `application_probe`
- 用户要求费曼法：`feynman_probe`

根据回答推进：

- 定义空白或错误：进入 Phase 7 微型补课，然后做定义检查。
- 定义部分正确：进入 Phase 4 苏格拉底追问。
- 定义良好：进入机制或边界问题。

## Phase 4：苏格拉底追问

目标：
- 在不过早给答案的情况下暴露缺失链接。

可问：
- “这个判断成立需要什么前提？”
- “哪个变量最先变化？”
- “如果这个假设不成立，哪里会断？”
- “它和旁边那个概念为什么不是一回事？”

进入 Phase 5 的条件：
- 用户已有足够碎片，可以尝试完整解释。

进入 Phase 7 的条件：
- 同一个缺口连续两次暴露，或用户要求帮助。

## Phase 5：费曼复述

要求用户不用来源材料中的术语堆叠，向初学者解释该概念。

观察：
- 循环定义。
- 因果步骤缺失。
- 用术语替代解释。
- 适用范围过度泛化。
- 没有例子或反例。

复述后进入 Phase 6。

## Phase 6：缺口定位

定位最小可用缺口：

- 定义缺口：术语没有和相邻概念区分开。
- 范围缺口：适用和不适用场景混在一起。
- 机制缺口：变量关系或状态转移缺失。
- 边界缺口：不能识别反例。
- 对比缺口：把邻近概念合并了。
- 迁移缺口：不能把概念应用到新问题。
- 自我定位缺口：用户不知道自己哪里说不清。

然后选择：
- 具体纠偏进入 Phase 7。
- 模型基本闭合时进入 Phase 8。

## Phase 7：微型补课

规则：
- 只修正已经定位的缺口。
- 解释要短。
- 尽量沿用用户回答中的词。
- 以 1 个检查问题结束。

避免：
- 完整讲座。
- 罗列大量事实。
- 引入无关概念。

## Phase 8：迁移题或反例题

选择一种：

- 改变关键变量的新场景。
- 该概念不应适用的边界案例。
- 看起来相似但机制不同的近似概念。
- 调试案例，让用户指出失效前提。

进入 Phase 9 的条件：
- 用户完成迁移，或剩余薄弱点已经清楚。

## Phase 9：总结薄弱点和下一步

包含：
- 使用材料。
- 强项。
- 薄弱点。
- 1 个下一步练习任务。
- 如果本轮暴露出可复用材料，给出可选候选笔记 proposal。

除非由其他治理 skill 处理写入，否则不要写入知识库。
